# applyDiff.js 명세서

가상 DOM 트리와 실제 DOM 트리를 비교해 **바뀐 부분만 실제 DOM에 반영**하는
간이 diff 알고리즘. 처음부터 다시 구현할 때 충족해야 할 요구사항을 정리한 문서다.

---

## 1. 목적 (왜 필요한가)

`registry.renderRoot()`는 매 렌더마다 **완전히 새로운 DOM 트리**를 만들어 반환한다.
이걸 그대로 통째로 갈아끼우면 동작은 하지만:

- 화면 전체가 다시 그려져 **깜빡임(flickering)** 이 생긴다
- 포커스, 스크롤 위치, `input`의 커서 위치 등 **DOM 상태가 날아간다**
- 브라우저의 리플로우/리페인트 비용이 크다

그래서 새 트리를 통째로 교체하는 대신, 실제 트리와 비교해서
**정말 달라진 노드만 최소한으로 손대는** 것이 이 모듈의 역할이다.

---

## 2. 만들어야 할 함수

| 이름            | 인자                                    | 반환            | 공개 여부          |
| --------------- | --------------------------------------- | --------------- | ------------------ |
| `applyDiff`     | `parentNode`, `realNode`, `virtualNode` | 없음 (부수효과) | **default export** |
| `isNodeChanged` | `node1`, `node2`                        | `boolean`       | 모듈 내부          |

- **`parentNode`**: `realNode`의 부모. 새 노드를 추가해야 할 때 필요하다.
- **`realNode`**: 현재 화면에 실제로 붙어 있는 노드 (없을 수 있음)
- **`virtualNode`**: 새로 렌더링된, 아직 화면에 없는 노드 (없을 수 있음)
- `applyDiff`는 반환값 없이 실제 DOM을 제자리에서(in-place) 변경하는 함수다.

---

## 3. `applyDiff`의 요구사항

아래 네 가지 경우를 **위에서부터 순서대로** 판단하고, 하나에 해당하면 즉시 종료한다.

1. **노드 삭제** — real은 있고 virtual은 없을 때.
   새 트리에 그 자리가 없다는 뜻이므로 실제 노드를 화면에서 제거한다.
2. **노드 추가** — real은 없고 virtual은 있을 때.
   새로 생긴 자리이므로 `parentNode`에 붙인다. 여기서만 `parentNode`가 쓰인다.
3. **노드 교체** — 둘 다 있고 `isNodeChanged`가 참일 때.
   하위를 더 볼 것 없이 실제 노드를 가상 노드로 통째로 갈아끼우고 **재귀를 중단**한다.
4. **자식으로 재귀** — 둘 다 있고 자기 자신은 동일할 때.
   자식 목록을 **인덱스로 짝지어** 각 쌍에 대해 자기 자신을 다시 호출한다.

### 자식 재귀에서 반드시 지킬 것

- 양쪽 자식 개수가 다를 수 있으므로 **긴 쪽 길이를 기준으로** 순회한다.
  짧은 쪽은 값이 비게 되고, 그 빈 자리가 위의 (1)/(2)로 흡수되어 추가/삭제가 처리된다.
- 빈 칸을 건너뛰는 순회 방식을 쓰면 안 된다. 인덱스로 처음부터 끝까지 도는 방식이어야 한다.
- 재귀할 때 부모 자리에는 **가상 노드가 아니라 실제 노드**를 넘긴다.
- 자식은 요소 목록만 다룬다. 유사 배열이므로 배열로 변환해 쓰는 편이 안전하다.

---

## 4. `isNodeChanged`의 요구사항

아래 세 조건 중 **하나라도** 해당하면 "변경됨"으로 판정한다.

1. **속성 개수가 다르다.**
2. **같은 이름의 속성인데 값이 다르다.**
   - 한쪽 노드의 속성을 순회하며 같은 이름의 값을 양쪽에서 비교한다.
   - 1번에서 개수가 같음이 보장되므로 한쪽만 순회해도 충분하다.
   - 속성 목록도 유사 배열이라 배열로 변환해 다룬다.
3. **양쪽 다 자식 요소가 없는 리프 노드인데 텍스트 내용이 다르다.**
   - **반드시 리프일 때만** 텍스트를 비교해야 한다.
     자식이 있는 노드의 텍스트는 하위 텍스트를 전부 합친 값이라,
     이걸 비교하면 하위 한 글자만 바뀌어도 상위 트리 전체가 교체되어 diff가 무의미해진다.

셋 다 아니면 "변경 없음"이고, 호출자는 자식으로 내려간다.

---

## 5. 충족해야 할 요구사항 체크리스트

- [ ] real만 있으면 노드를 제거한다
- [ ] virtual만 있으면 `parentNode`에 추가한다
- [ ] 변경 판정 시 노드를 교체하고 하위 재귀를 중단한다
- [ ] 변경이 없으면 자식들로 재귀한다
- [ ] 자식 개수가 다를 때 긴 쪽 기준으로 순회한다 (추가/삭제 처리)
- [ ] 재귀 시 부모로 실제 노드를 넘긴다
- [ ] 속성 개수 차이를 감지한다
- [ ] 속성 값 차이를 감지한다
- [ ] 리프 노드일 때만 텍스트를 비교한다
- [ ] 속성/자식 유사 배열을 배열로 변환해 다룬다
- [ ] `applyDiff`를 default export 한다

## 6. 호출 전제 조건

- `index.js`의 렌더 루프가 "현재 실제 루트 요소"와 "새로 렌더된 트리"를 넘겨 호출한다.
- `renderRoot`가 실제 루트를 **복제해서** 새 트리를 만들기 때문에, 호출 시점에
  실제 노드는 여전히 화면에 붙어 있고 새 트리는 어디에도 붙어 있지 않은 상태다.
  이 둘을 비교하는 것이 이 함수의 전제다.

---

## 7. 한계 / 주의사항 (의도적으로 단순한 알고리즘임)

- **키(key) 개념이 없다.** 자식을 **인덱스로만** 짝짓기 때문에,
  리스트 맨 앞에 항목 하나가 추가되면 그 뒤 모든 노드가 "변경됨"으로 판정되어
  줄줄이 교체된다. React의 `key` prop이 해결하는 문제를 여기서는 다루지 않는다.
- **텍스트 노드를 직접 다루지 않는다.** 자식 목록에는 요소만 담기므로
  요소 사이에 섞인 순수 텍스트 노드는 diff 대상이 아니다.
  리프의 텍스트 비교로 간접 처리될 뿐이다.
- **DOM 프로퍼티는 비교하지 않는다.** `input`의 값이나 체크 상태 같은 것은
  속성(attribute)이 아니라 프로퍼티(property)라 속성 비교에 잡히지 않는다.
- 최초 렌더에서는 실제 노드와 새 트리가 이미 둘 다 존재하므로 (2) 경로는 잘 타지 않고,
  주로 하위 리스트의 증감에서 (1)/(2)가 발동한다.
